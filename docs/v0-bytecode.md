# SVM v0 բայթ-կոդ

Այս փաստաթուղթը նկարագրում է պահոցի սկզբնական բայթ-կոդը։ Այն նախատեսված է որպես migration baseline և չի սահմանափակում SVM v1-ի ձևաչափը։

## Հիմնական հատկությունները

- հիշողության չափը՝ 16 ԿԲ,
- հիշողությունը հասցեավորվում է բայթերով,
- ամբողջ արժեքը՝ նշանով 32 բիթ,
- բազմաբայթ արժեքների դասավորությունը՝ little-endian,
- սկզբնական `IP`՝ `0`,
- սկզբնական `SP`՝ ծրագրի վերջին բայթից անմիջապես հետո,
- ստեկի աճի ուղղությունը՝ դեպի մեծ հասցեներ։

Բեռնված ծրագիրը հում բայթերի հաջորդականություն է և header կամ version դաշտ չունի։ Կատարումը շարունակվում է մինչև `HALT` հրամանը։

## Հրամանի առաջին բայթը

Առաջին բայթի ստորին 6 բիթերը opcode-ն են, իսկ վերին 2 բիթերը որոշում են հրամանի չափն ու operand-ի ձևը։

| Վերին բիթեր | Անուն | Հրամանի չափ | Operand |
|---|---|---:|---|
| `00` | Basic | 1 բայթ | չկա |
| `01` | Immediate | 5 բայթ | նշանով 32-բիթանոց թիվ |
| `10` | Indirect | 3 բայթ | 16-բիթանոց հասցեային դաշտ |
| `11` | Reserved | — | անվավեր է |

Immediate և հասցեային operand-ները կոդավորվում են little-endian կարգով։

## Opcode-ներ

| Կոդ | Հրաման | Եղանակ |
|---:|---|---|
| 0 | `NOP` | Basic |
| 1 | `PUSH` | Immediate կամ Indirect |
| 2 | `POP` | Indirect |
| 3 | `CALL` | Indirect |
| 4 | `RET` | Basic |
| 5 | `JUMP` | Indirect |
| 6 | `JZ` | Indirect |
| 7 | `HALT` | Basic |
| 8 | `INPUT` | Basic |
| 9 | `PRINT` | Basic |
| 10–24 | թվաբանական, բիթային և համեմատման հրամաններ | Basic |

10–24 կոդերին հերթականությամբ համապատասխանում են `ADD`, `SUB`, `MUL`, `DIV`, `MOD`, `NEG`, `AND`, `OR`, `NOT`, `EQ`, `NE`, `LT`, `LE`, `GT`, `GE` հրամանները։

## Հարաբերական հասցե

`PUSH` և `POP` հրամանների 16-բիթանոց հասցեային դաշտի վերին երկու բիթերը ցույց են տալիս բազային ռեգիստրը։ Ստորին 14 բիթերը նշանով displacement-ն են։

| Բիթեր | Ռեգիստր |
|---|---|
| `01` | `SP` |
| `10` | `FP` |
| `11` | `IP` |
| `00` | անվավեր |

Displacement-ի միջակայքը `[-8192, 8191]` է, իսկ արդյունավետ հասցեն հաշվվում է այսպես՝

```text
address = register + displacement
```

`CALL`, `JUMP` և `JZ` հրամանները 16-բիթանոց դաշտն օգտագործում են որպես բացարձակ ծրագրային հասցե։

## Ֆունկցիայի կանչի կադրը

`CALL`-ը ստեկում հաջորդաբար գրում է վերադարձի հասցեն և նախորդ `FP`-ը, ապա նոր `FP`-ը դնում է դրանցից անմիջապես հետո։

```text
փոքր հասցեներ

... արգումենտներ ...
[FP - 8] վերադարձի հասցե
[FP - 4] նախորդ FP
[FP + 0] առաջին լոկալ կամ operand

մեծ հասցեներ
```

Վերջին push արված արգումենտը գտնվում է `[FP - 12]` հասցեում։ Յուրաքանչյուր նախորդ արգումենտի հասցեն ևս 4-ով փոքր է։

`RET`-ը պահանջում է մեկ վերադարձվող արժեք `FP`-ից վերև։ Այն վերականգնում է հին `SP`, `FP` և `IP` արժեքները, ապա արդյունքը թողնում է caller-ի ստեկի գագաթին։ Արգումենտներն ինքնաբերաբար չեն հեռացվում․ սա v0 ABI-ի հայտնի սահմանափակում է։

## Սխալ կատարում

v0 VM-ը սահմանազանց հիշողության հասանելիությունը, ստեկի թերալցումը կամ գերլցումը, անվավեր opcode/addressing mode-ը, վնասված call frame-ը և զրոյի վրա բաժանումը կանգնեցնում է Go `panic`-ով։ SVM v1-ում դրանք նախատեսվում է փոխարինել typed trap-երով։
