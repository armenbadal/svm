# SVM v1 specification

Կարգավիճակ՝ **քննարկման նախագիծ 0.2**  
Թարմացված՝ 2026-09-13

SVM v1-ը փոքր ուսումնական ստեկային մեքենա է։ Այն պետք է բավական պարզ լինի գրատախտակի վրա ամբողջությամբ բացատրելու համար և միաժամանակ բավական ամբողջական՝ ուսումնական կոմպիլյատորի նպատակային մեքենա ծառայելու համար։

Այս փաստաթղթերը դեռ չեն նկարագրում ընթացիկ իրականացումը։ v0-ի փաստացի ձևաչափը նկարագրված է [`v0-bytecode.md`](v0-bytecode.md)-ում։

## Նպատակներ

- Ցուցադրել fetch–decode–execute ցիկլը։
- Ցուցադրել ստեկային հաշվարկը և ֆունկցիայի call frame-ը։
- Տրամադրել assembler-ով և Go Builder API-ով նույն բայթ-կոդը կառուցելու հնարավորություն։
- Աշխատել և՛ որպես ինքնուրույն command-line VM, և՛ որպես Go գրադարան։
- Կատարել թվաբանություն, պայմաններ, ցիկլեր, ֆունկցիաներ, recursion, globals, arrays, string-եր և պարզ I/O։
- Անվավեր input-ի դեպքում վերադարձնել հասկանալի սխալ՝ առանց Go panic-ի։

## Ոչ նպատակներ

SVM v1.0-ը չի փորձում լինել օպերացիոն համակարգ, sandbox կամ production runtime։ Այն չի ներառում՝

- virtual memory և memory protection,
- heap allocator կամ garbage collector,
- object files և linker,
- dynamic libraries,
- syscall ABI,
- function descriptor table,
- JIT, threads կամ floating-point,
- executable-ի symbol/debug section-ներ,
- macro assembler։

Այս հնարավորությունները կարող են ավելացվել միայն այն ժամանակ, երբ կոնկրետ ուսումնական կամ compiler պահանջ առաջանա։

## Կառուցվածքը

```text
assembly source ──> assembler ──┐
                                ├──> bytecode.Builder ──> Program ──> .svm
compiler AST/IR ────────────────┘                              │
                                                              ▼
                                              Machine.Load → Run/Step
```

Համակարգն ունի միայն չորս հիմնական մաս՝

- `bytecode` — հրամաններ, Builder և փոքր executable header,
- `assembler` — տեքստից `Program`,
- `machine` — հիշողություն, երեք ռեգիստր և կատարման ցիկլ,
- `cmd/svm` — assemble/run հրամանային գործիք։

## Հիմնական որոշումներ

- Մեքենայի արժեքը նշանով 32-բիթանոց ամբողջ թիվ է։
- Ստատիկ հասցեները և branch target-ները բայթ-կոդում 16 բիթ են։
- Մեքենայի հիշողությունը առավելագույնը 64 ԿԲ է։
- Հիշողությունը հասցեավորվում է բայթերով և little-endian է։
- Կան միայն `IP`, `SP` և `FP` ռեգիստրները։
- Կոդը գտնվում է `0` հասցեից, տվյալները՝ կոդից հետո, ստեկը՝ տվյալներից հետո։
- Ստեկն աճում է դեպի մեծ հասցեներ, իսկ `SP`-ն ցույց է տալիս հաջորդ ազատ բայթը։
- Հրամանի առաջին բայթի վերին երկու բիթերը ցույց են տալիս operand-ի ձևը, ստորին վեցը՝ opcode-ը։
- Ֆունկցիաները ստանում են արգումենտները ստեկով և ավարտվում են `RET n` հրահանգով։
- Լոկալները հատկացնում են սովորական `PUSH 0` հրահանգները։
- `INPUT` և `PRINT` իրական հրամաններ են, բայց աշխատում են Machine-ին փոխանցված `io.Reader`/`io.Writer` հոսքերով։

## Համատեղելիություն

SVM v1-ը նոր ձևաչափ է և պարտադիր չէ, որ կատարի v0 հում բայթ-կոդը։ Assembler-ը կարող է պահպանել v0 source syntax-ի մեծ մասը։ `.svm` magic-ի version բայթը loader-ին թույլ է տալիս տարբերել ձևաչափերը։

## «Լիարժեք» լինելու չափանիշը

SVM v1.0-ը պատրաստ է համարվում, եթե assembler-ով և Builder API-ով հնարավոր է կառուցել ու նույն արդյունքով կատարել՝

- թվաբանական արտահայտություն,
- `if` և `while`,
- մի քանի արգումենտով ֆունկցիա,
- recursive factorial,
- global փոփոխական,
- array կամ string traversal,
- input/output ծրագիր։

## Վերանայման բաց հարցեր

1. Հիշողության default չափը պահե՞լ 16 ԿԲ, իսկ առավելագույնը՝ 64 ԿԲ։
2. 12-բայթանոց executable header-ը բավարա՞ր է։
3. `RET n`-ի `n`-ը slot count լինելը հարմա՞ր է։
4. Dynamic `STORE`-ի stack order-ը `[value address]` ճի՞շտ ընտրություն է։
5. Չհավասարեցված 32-բիթանոց memory access-ը թույլատրե՞լ պարզության համար։
6. `INPUT` և `PRINT` հրամանները բավակա՞ն են առաջին portable I/O-ի համար։
