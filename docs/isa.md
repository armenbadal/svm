# SVM v1 հրամանների հավաքածու

Կարգավիճակ՝ **քննարկման նախագիծ 0.2**

## Հրամանի կոդավորում

Հրամանի առաջին բայթի ստորին վեց բիթերը opcode-ն են։ Վերին երկու բիթերը որոշում են operand-ի ձևը և հրահանգի ամբողջ չափը։

| Բիթեր | Անուն | Operand | Հրամանի չափ |
|---|---|---|---:|
| `00` | Basic | չկա | 1 բայթ |
| `01` | Immediate | նշանով 32-բիթանոց թիվ | 5 բայթ |
| `10` | Short | աննշան 16-բիթանոց դաշտ | 3 բայթ |
| `11` | Reserved | անվավեր | — |

Բազմաբայթ operand-ները little-endian են։ Յուրաքանչյուր opcode-ի համար թույլատրելի mode-երը տրված են ստորև։ Այլ mode-ով հրահանգը անվավեր է։

Այս ձևաչափը դիտավորյալ սահմանափակում է ISA-ն 64 opcode-ով։ Դա բավարար է ուսումնական մեքենայի համար և decode փուլը պահում է տեսանելի։

## Stack notation

Ստեկի նկարագրությունում աջ կողմի արժեքը գագաթն է։

```text
[... left right] → [... result]
```

նշանակում է, որ նախ հանվում է `right`, ապա `left`, և ավելացվում է `result`։

## Opcode-ներ

v0-ի գոյություն ունեցող opcode-ները պահպանում են իրենց 0–24 արժեքները։ Նոր հրամաններն ավելացվում են դրանցից հետո։

| Կոդ | Հրաման | Mode | Stack effect |
|---:|---|---|---|
| `0` | `NOP` | Basic | `[] → []` |
| `1` | `PUSH` | Immediate կամ Short | `[] → [value]` |
| `2` | `POP` | Short | `[value] → []` |
| `3` | `CALL` | Short | ստեղծում է call frame |
| `4` | `RET` | Basic կամ Short | վերադարձնում է մեկ արժեք |
| `5` | `JUMP` | Short | `[] → []` |
| `6` | `JZ` | Short | `[condition] → []` |
| `7` | `HALT` | Basic | `[] → []` |
| `8` | `INPUT` | Basic | `[] → [value]` |
| `9` | `PRINT` | Basic | `[value] → []` |
| `10` | `ADD` | Basic | `[a b] → [a+b]` |
| `11` | `SUB` | Basic | `[a b] → [a-b]` |
| `12` | `MUL` | Basic | `[a b] → [a*b]` |
| `13` | `DIV` | Basic | `[a b] → [a/b]` |
| `14` | `MOD` | Basic | `[a b] → [a%b]` |
| `15` | `NEG` | Basic | `[a] → [-a]` |
| `16` | `AND` | Basic | `[a b] → [a&b]` |
| `17` | `OR` | Basic | `[a b] → [a\|b]` |
| `18` | `NOT` | Basic | `[a] → [^a]` |
| `19` | `EQ` | Basic | `[a b] → [a==b]` |
| `20` | `NE` | Basic | `[a b] → [a!=b]` |
| `21` | `LT` | Basic | `[a b] → [a<b]` |
| `22` | `LE` | Basic | `[a b] → [a<=b]` |
| `23` | `GT` | Basic | `[a b] → [a>b]` |
| `24` | `GE` | Basic | `[a b] → [a>=b]` |
| `25` | `DROP` | Basic | `[x] → []` |
| `26` | `DUP` | Basic | `[x] → [x x]` |
| `27` | `SWAP` | Basic | `[a b] → [b a]` |
| `28` | `XOR` | Basic | `[a b] → [a^b]` |
| `29` | `SHL` | Basic | `[value count] → [result]` |
| `30` | `SHR` | Basic | `[value count] → [result]` |
| `31` | `JNZ` | Short | `[condition] → []` |
| `32` | `LOAD` | Basic | `[address] → [value]` |
| `33` | `STORE` | Basic | `[value address] → []` |
| `34` | `LOADB` | Basic | `[address] → [value]` |
| `35` | `STOREB` | Basic | `[value address] → []` |

36–63 opcode-ները պահուստային են։

## Ստեկային հրամաններ

### `PUSH number`

Immediate mode-ով ստեկ է դնում նշանով 32-բիթանոց թիվը։ Օրինակ՝ `PUSH -12` հրամանի չափը 5 բայթ է։

### `PUSH [register ± displacement]`

Short mode-ով հաշվում է հարաբերական հասցեն, այնտեղից կարդում է 32-բիթանոց արժեք և այն դնում ստեկում։ Հասցեի 16-բիթանոց ձևը նկարագրված է [`memory.md`](memory.md)-ում։

`SP`-relative ձևը հասցեն հաշվում է մինչև նոր արժեքի push-ը։ `IP`-relative ձևի հիմքը հաջորդ instruction-ի հասցեն է։

### `POP [register ± displacement]`

Հանում է ստեկի գագաթը և գրում է հարաբերական հասցեում որպես 32-բիթանոց արժեք։ Հասցեն ամբողջությամբ ստուգվում է մինչև արժեքը ստեկից հանելը։

`SP`-relative ձևը հասցեն հաշվում է մինչև արժեքի pop-ը։ `IP`-relative ձևի հիմքը հաջորդ instruction-ի հասցեն է։

### `DROP`, `DUP`, `SWAP`

- `DROP`-ը հեռացնում է գագաթի արժեքը։
- `DUP`-ը կրկնօրինակում է գագաթի արժեքը։
- `SWAP`-ը փոխանակում է վերին երկու արժեքները։

Լոկալների համար հատուկ հատկացման հրահանգ չկա։ Յուրաքանչյուր լոկալ սկզբնավորվում է սովորական `PUSH 0`-ով։

## Հիշողության հրամաններ

`LOAD` և `STORE` հրամանները հնարավորություն են տալիս աշխատել runtime-ում հաշվված հասցեներով՝ arrays և pointers իրականացնելու համար։

- `LOAD`-ը ստեկի հասցեից կարդում է 32-բիթանոց արժեք։
- `STORE`-ը սպասում է արժեք, ապա դրա վերևում հասցե, և գրում է 32-բիթանոց արժեքը։
- `LOADB`-ը կարդում է մեկ բայթ և zero-extend է անում մինչև 32 բիթ։
- `STOREB`-ը գրում է արժեքի ստորին 8 բիթը։

Ստեկից վերցված հասցեն մեկնաբանվում է որպես աննշան 32-բիթանոց թիվ և պետք է տեղավորվի մեքենայի հիշողությունում։ Սխալ հասցեի դեպքում ստեկն ու հիշողությունը չեն փոխվում։

Static data label-ի հասցեն ստեկ դնելու assembler ձևը `PUSH @label` է։ Այն կոդավորվում է որպես Immediate `PUSH`՝ label-ի լուծված հասցեով։

## Թվաբանություն

Գործողություններն աշխատում են նշանով 32-բիթանոց արժեքներով։ `ADD`, `SUB`, `MUL` և `NEG` overflow-ը wraparound է modulo `2^32`։

`DIV`-ը կլորացվում է դեպի զրո։ `DIV` կամ `MOD` զրոյի վրա runtime error է։ `MinInt32 / -1` արդյունքը `MinInt32` է, իսկ մնացորդը՝ `0`։

`AND`, `OR`, `XOR` և `NOT` հրամանները աշխատում են հում 32-բիթանոց bit pattern-ներով։ `SHL` և `SHR` shift count-ը պետք է լինի `[0, 31]` միջակայքում։ `SHR`-ը arithmetic right shift է։

## Համեմատումներ և պայմաններ

Համեմատումները նշանով են։ Ճշմարիտ արդյունքը `1` է, կեղծը՝ `0`։

`JZ`-ն անցում է կատարում, եթե պայմանը `0` է։ `JNZ`-ն անցում է կատարում, եթե պայմանը `0` չէ։ Երկուսն էլ միշտ հեռացնում են պայմանը ստեկից։

`JUMP`, `JZ`, `JNZ` և `CALL` Short operand-ը բացարձակ 16-բիթանոց code հասցե է և պետք է ցույց տա հրահանգի առաջին բայթը։

## Ֆունկցիայի հրամաններ

`CALL`-ը պահպանում է վերադարձի հասցեն ու հին `FP`-ը և ստեղծում նոր frame։ `RET n`-ը վերադարձնում է մեկ արժեք ու հեռացնում caller-ի `n` արգումենտները։ Basic `RET`-ը համարժեք է `RET 0`-ին։ Մանրամասն վարքը նկարագրված է [`abi.md`](abi.md)-ում։

## Մուտք և ելք

### `INPUT`

Machine-ի input հոսքից կարդում է whitespace-ով առանձնացված մեկ տասնորդական `int32`։ Հաջողության դեպքում արժեքը դրվում է ստեկում։ EOF-ը կամ անվավեր թիվը runtime error է։

### `PRINT`

Հանում է ստեկի գագաթի `int32` արժեքը և Machine-ի output հոսքում գրում է դրա տասնորդական ներկայացումն ու newline։ Output սխալի դեպքում վերադարձվում է runtime error։

VM գրադարանն ինքնուրույն չի օգտագործում `os.Stdin` կամ `os.Stdout`։ CLI-ն է դրանք փոխանցում Machine-ին։

## `HALT`

Ավարտում է ծրագիրը հաջողությամբ և չի փոխում ստեկը։ SVM v1.0-ը առանձին process exit code չի սահմանում։ CLI-ի հաջող կատարումն ավարտվում է `0` exit code-ով, runtime error-ը՝ ոչ զրոյականով։

## Runtime error-ներ

Առաջին տարբերակում բավական է մեկ պարզ կառուցվածքային սխալ՝

```go
type RuntimeError struct {
    IP      uint32
    Message string
}
```

Runtime error են՝

- code սահմաններից դուրս instruction fetch-ը,
- անհայտ opcode կամ սխալ mode-ը,
- կտրված operand-ը,
- հիշողության սահմանազանց հասանելիությունը,
- stack underflow/overflow-ը,
- զրոյի վրա բաժանումը,
- անվավեր shift count-ը,
- անվավեր branch target-ը,
- վնասված call frame-ը,
- input/output սխալը։

`Run()` և `Step()` մեթոդները վերադարձնում են error և սովորական ծրագրային սխալի համար Go panic չեն առաջացնում։
