# SVM v1 հիշողության մոդել

Կարգավիճակ՝ **քննարկման նախագիծ 0.2**

## Հիշողություն

SVM v1-ն ունի մեկ գծային բայթային հիշողություն։ Դրա չափը runtime-ը ընտրում է ծրագրի բեռնման ժամանակ և այն չի կարող գերազանցել 65536 բայթը։ Առաջարկվող default-ը 16 ԿԲ է։

| Հասկացություն | Ներկայացում |
|---|---|
| Բայթ | աննշան 8 բիթ |
| Մեքենայի արժեք | նշանով 32 բիթ, two's complement |
| Բայթ-կոդում հասցե | աննշան 16 բիթ |
| Byte order | little-endian |

Մեքենայի ռեգիստրները runtime-ում պահվում են առնվազն 32 բիթով։ Դա թույլ է տալիս `SP`-ին ներկայացնել նաև 65536 արժեքը՝ ամբողջ հիշողությունից անմիջապես հետո գտնվող դիրքը։ Բայթ-կոդում գրված ստատիկ հասցեն շարունակում է լինել 16-բիթանոց։

## Ռեգիստրներ

```go
type Machine struct {
    IP uint32
    SP uint32
    FP uint32

    memory []byte
}
```

| Ռեգիստր | Նշանակություն |
|---|---|
| `IP` | հաջորդ կատարվող հրահանգի հասցե |
| `SP` | ստեկի հաջորդ ազատ բայթի հասցե |
| `FP` | ընթացիկ ֆունկցիայի frame base-ը կամ `0`, եթե ակտիվ կանչ չկա |

Ծրագիրը չի կարող անմիջապես արժեք վերագրել ռեգիստրներին։ Դրանք փոխվում են հրահանգների կատարմամբ։

## Ծրագրի դասավորությունը

```text
0                                                       memory_size
│                                                            │
├──── code ────┬─ padding ─┬──── data ────┬─ padding ─┬─ stack →
│              │           │              │           │
0          code_size   data_base      image_end   stack_base
```

Loader-ը հաշվում է՝

```text
data_base  = align_up(code_size, 4)
image_end  = data_base + data_size
stack_base = align_up(image_end, 4)
stack_limit = memory_size
```

Header-ը VM հիշողության մեջ չի բեռնվում։ Code label-ի հասցեն code-ի offset-ն է։ Data label-ի հասցեն `data_base + data_offset` է։ Padding բայթերը զրոյացվում են։

SVM v1.0-ում առանձին read-only data, BSS և heap չկան։ `.zero` directive-ը data հատվածում իրական զրո բայթեր է պահում executable-ում։ Stack-ից հետո մնացած ազատ հիշողությունը հատուկ allocator չունի։

## Սկզբնական վիճակ

Հաջող `Load`-ից հետո՝

```text
IP = entry
SP = stack_base
FP = 0
```

Ամբողջ հիշողությունը նախ զրոյացվում է, ապա code և data բայթերը պատճենվում են։ Նոր `Load` կամ `Reset` գործողությունը չի պահպանում նախորդ կատարման վիճակը։

## Ստեկ

Ստեկի յուրաքանչյուր արժեք զբաղեցնում է 4 բայթ։ `SP`-ն ցույց է տալիս հաջորդ ազատ դիրքը։

```text
PUSH(value):
    memory32[SP] = value
    SP = SP + 4

POP():
    SP = SP - 4
    value = memory32[SP]
```

Սովորական stack instruction-ի ստորին սահմանը `stack_base`-ն է, եթե `FP == 0`, և ընթացիկ `FP`-ն՝ ակտիվ ֆունկցիայի ներսում։ Այդ սահմանից ներքև գտնվում են caller-ի արժեքներն ու call frame-ի ծառայողական դաշտերը։ Սահմանից վերև մեկ ամբողջ slot չլինելու դեպքում pop-ը stack underflow է։ `SP + 4 > memory_size` վիճակում push-ը stack overflow է։ Սխալի դեպքում `SP`-ն և հիշողությունը չեն փոխվում։

Ֆունկցիայի frame-ի ծառայողական արժեքները նույնպես գտնվում են նույն ստեկում և նկարագրված են [`abi.md`](abi.md)-ում։

## Հիշողության հասանելիություն

32-բիթանոց բեռնումն ու գրառումը կարդում կամ գրում են չորս հաջորդական little-endian բայթ։ Պարզության համար SVM v1-ը թույլ է տալիս չհավասարեցված 32-բիթանոց հասցեներ։ Assembler-ը և compiler-ը, այնուամենայնիվ, պետք է սովորաբար 4-ի հավասարեցնեն բառերն ու stack slot-երը։

Հասանելիությունն անվավեր է, եթե՝

```text
address + size > memory_size
```

Հաշվարկը կատարվում է լայն թվային տեսքով, որպեսզի `address + size`-ը չկարողանա overflow անել։ Սխալ memory access-ը վերադարձնում է runtime error և չի կատարում մասնակի գրառում։

Հիշողության իրավունքներ չկան։ Ծրագիրը տեխնիկապես կարող է գրել նաև code բայթերի վրա։ Սա դիտավորյալ պարզ von Neumann մոդել է։ Instruction fetch-ը, սակայն, կարող է կատարվել միայն `[0, code_size)` միջակայքից։

## Հարաբերական հասցեավորում

`PUSH [FP + d]`, `POP [FP + d]`, `PUSH [SP + d]` և նման հրահանգները օգտագործում են 16-բիթանոց հարաբերական հասցեային operand։ Դրա ստորին 14 բիթերը նշանով displacement-ն են, իսկ վերին երկուսը՝ բազային ռեգիստրը։

| Վերին բիթեր | Ռեգիստր |
|---|---|
| `01` | `SP` |
| `10` | `FP` |
| `11` | `IP` |
| `00` | անվավեր |

Displacement-ի միջակայքը `[-8192, 8191]` է։ Արդյունավետ հասցեն՝

```text
address = register + displacement
```

Բացասական կամ 65535-ից մեծ արդյունքը runtime error է։

Ռեգիստրի արժեքը վերցվում է instruction-ի operand-ն ամբողջությամբ կարդալուց հետո, բայց մինչև նրա stack effect-ը։ Հետևաբար `SP`-relative հասցեն օգտագործում է push/pop-ից առաջ եղած `SP`-ն, իսկ `IP`-relative հասցեն՝ հաջորդ instruction-ի հասցեն։

## Բեռնումից առաջ ստուգումներ

Loader-ը մերժում է ծրագիրը, եթե՝

- header-ը կամ body-ն կտրված է,
- code և data չափերը չեն տեղավորվում տրամադրված հիշողությունում,
- entry point-ը code-ի սահմաններից դուրս է,
- entry point-ը հրահանգի սկիզբ չէ,
- instruction stream-ում կա անհայտ opcode, սխալ operand mode կամ կտրված operand,
- static branch target-ը code instruction boundary չէ։
